# ED_Japanese Windows版 手動OCR 仕様書

**Status:** Draft  
**対象:** Elite Dangerous (Windows)  
**対象実装:** Windows環境での新規実装  
**対象外:** Linux/Bazzite版の移植・共通化

---

## 1. 目的

ユーザーがゲーム画面上で指定した矩形範囲を継続的にOCRし、翻訳結果を元テキストの位置に重ねて表示する。

また、OCR結果の原文を別ウィンドウに出力し、星系名・ステーション名等をコピーするために利用できるようにする。

本仕様では、ユーザーが監視範囲を明示的に指定する。全画面からの自動的なテキスト領域検出は本仕様の対象外とし、将来拡張とする。

### 1.1 設計方針

- Windows向けに新規実装する。Linux/Bazzite版のキャプチャ・Overlay実装を直接移植しない。
- OS依存処理はWindows側で完結させる。
- OCRエンジンはRapidOCRを使用し、Windows化を理由に別エンジンへ変更しない。
- OCR結果のBBoxを保持し、翻訳Overlayの位置決めに使用する。
- Overlayは現在状態から毎回描画する状態駆動方式とし、前回描画内容の消去に依存しない。
- ED本体のウィンドウキャプチャを使用し、Overlay自己汚染を構造的に防止する。

---

## 2. 用語

| 用語 | 定義 |
|---|---|
| 監視範囲 | ユーザーが指定した矩形。OCR入力範囲 |
| Line | OCRが返す1行分のテキストとBBox |
| BBox | Lineの矩形座標。監視範囲内の相対座標 |
| 翻訳候補 | Filterを通過し、翻訳対象と判定されたLine |
| 保護語 | 翻訳せず原文のまま維持する固有名詞 |
| Overlay | ゲーム画面上に翻訳を重ねて表示する表示層 |
| 原文Window | OCR原文を一覧表示する通常ウィンドウ |
| OverlayState | 現在表示すべき翻訳Lineを保持する状態 |
| Cache HIT | 同一原文の翻訳結果がTranslation Cacheに存在する状態 |
| Cache MISS | 同一原文の翻訳結果がTranslation Cacheに存在しない状態 |

## 4. キャプチャ

### 4.1 キャプチャ対象

Elite Dangerousの**対象ウィンドウ**をキャプチャする。

デスクトップ全体・モニター全体のキャプチャは使用しない。

理由はOverlay自己汚染の防止である（§11参照）。

### 4.2 前提条件

ウィンドウキャプチャを使用するため、EDは以下のいずれかで動作している必要がある。

- ボーダーレスウィンドウ
- ウィンドウモード

排他的フルスクリーンは対象外とする。

起動時に対象EDウィンドウを取得できない場合、ユーザーに明示的に通知して起動を中止する。

対象ウィンドウが起動後に閉じられた場合も、キャプチャ停止を検出してエラー状態へ遷移する。

### 4.3 キャプチャ座標

キャプチャ画像はEDウィンドウの**クライアント領域**を基準とする。

監視範囲はクライアント領域内の相対座標で保持する。

```text
ED Client Image
+----------------------------------+
|                                  |
|       monitoring region          |
|       x,y,w,h                    |
|                                  |
+----------------------------------+
```

Overlay描画時のみ、監視範囲内相対座標 → EDクライアント座標 → スクリーン座標へ変換する。

これにより、EDウィンドウを移動しても監視範囲はEDに追従する。

### 4.4 ウィンドウサイズ変更

EDクライアント領域のサイズが監視範囲保存時と異なった場合、監視範囲を自動補正しない。

安全のため、以下のいずれかを実施する。

- 監視を停止し、再指定を要求する
- または設定された範囲が新しいクライアント領域内に収まることを検証し、収まらない場合のみ再指定を要求する

本仕様では解像度・UIスケール変更時の自動座標補正を行わない。

## 5. 監視範囲の指定

### 5.1 指定操作

ショートカットキーで範囲指定モードに入る。

範囲指定モードでは、EDクライアント画像を基準に矩形の始点・終点をユーザーが指定する。

確定後、矩形を正規化して以下の形式で保持する。

```yaml
ocr:
  region:
    x: 360
    y: 850
    width: 1200
    height: 150
```

`x`、`y`、`width`、`height` はEDクライアント領域内のピクセル単位とする。

### 5.2 入力

範囲指定中は範囲指定UIが入力を取得するため、EDへの通常入力は受け付けない。

ゲーム内時間は停止しないため、飛行中・戦闘中の使用は想定しない。

### 5.3 保持

確定した矩形は設定ファイルへ保存し、アプリ再起動後も復元する。

解像度、ウィンドウサイズ、UIスケール等が変わった場合は自動補正しない。必要に応じてユーザーが再指定する。

### 5.4 不正な範囲

以下の場合は監視を開始しない。

- widthまたはheightが0以下
- EDクライアント領域外にはみ出している
- キャプチャ画像サイズと整合しない

ユーザーには再指定を要求する。

## 6. 監視ループ

### 6.1 周期

目標周期は2fps、すなわち500ms間隔とする。

ただし、OCR処理が完了していない場合、次のOCR処理を同時実行しない。

OCRが1回あたり500msを超える場合、実効フレームレートは低下する。これは仕様上許容する。

実装は単一OCR処理を保証するsingle-flight方式とし、OCR処理の重複実行を行わない。

### 6.2 差分Gate

キャプチャした監視範囲が前回OCR対象フレームから変化していない場合、OCRを実行しない。

差分計算はOCRより前に実施する。

静止画面ではOCRを実行せず、CPU負荷を差分計算程度に抑える。

差分判定は単純な完全一致だけに依存せず、実装時に以下を検討する。

- グレースケール化
- 縮小画像での比較
- 差分率の閾値判定

アンチエイリアスや軽微な描画揺れで常時OCRが発生しない閾値を実測で決定する。

### 6.3 OCR結果の更新

新しいOCR結果が得られた時点で、以下を原子的に更新する。

- 現在のLine一覧
- 原文Window用データ
- 翻訳候補
- OverlayState

古いOverlayStateを部分的に残すことは禁止する。

## 7. OCR

### 7.1 エンジン

RapidOCRを使用する。

Windows版実装のために別OCRエンジンへ変更しない。

### 7.2 出力

各Lineについて以下を取得する。

- `text`
- `bbox`
- `confidence`

`bbox` は監視範囲内の相対座標として保持する。

BBoxは破棄しない。Overlayの位置決めおよびスクロール時の現在位置反映に必須である。

RapidOCRの標準出力では、検出した各テキスト行の`boxes`、認識文字列`txts`、信頼度`scores`を取得できる。また、全体の経過時間とDetection / Classification / Recognitionの各経過時間を取得できる。citeturn0search0turn0search2

### 7.3 ベースライン測定

実装初期に、Windows環境で監視範囲サイズごとのOCR所要時間を実測する。

既知の参考値として、FHD全画面で約899ms、Mission Board領域で700〜1080msがあるが、これらはLinux環境での測定値であり、Windows版の基準値として使用しない。

Windows版では少なくとも以下を記録する。

- キャプチャ時間
- Crop時間
- 前処理時間
- Detection時間
- Classification時間
- Recognition時間
- OCR全体時間
- OCR結果Line数

### 7.4 RapidOCRバージョン

実装時に使用するRapidOCRパッケージとバージョンを固定し、測定結果とともに記録する。

現在のRapidOCRでは`rapidocr_onnxruntime`等の旧パッケージから統合された`rapidocr`パッケージへの移行が進んでいるため、Windows実装では採用パッケージを明示的に固定する。citeturn0search3

## 8. 翻訳対象判定（Filter）

### 8.1 原則

監視範囲内の文字は原則としてすべてOCRする。

翻訳するかどうかはOCR結果に対するFilterで判定する。ユーザーが範囲指定によって個別に除外することを前提としない。

### 8.2 除外

以下に該当するLineは翻訳対象外とし、Overlayにも表示しない。

| 種別 | 判定例 |
|---|---|
| 金額 | `^\s*[\d,]+(?:\.\d+)?\s*CR\s*$` |
| 距離 | `^\s*[\d,]+(?:\.\d+)?\s*LY\s*$` |
| 重量・数量 | `^\s*[\d,]+(?:\.\d+)?\s*(t|kg|units?)\s*$` |
| 評判・影響 | 設定可能なREP/INF定型パターン |
| 純数値 | `^\s*[\d,]+(?:\.\d+)?\s*$` |
| 記号のみ | Unicode上の文字・数字を1文字も含まない文字列 |
| 低信頼度 | `confidence`が設定閾値未満 |

「記号のみ」はASCIIの英数字だけを基準にしてはならない。日本語やその他のUnicode文字を含むタイトルを誤って除外しないこと。

### 8.3 未知パターンの扱い

判定不能・未知のパターンは翻訳対象として残す。

不要な文字列を翻訳してしまうことより、誤って除外してミッションタイトル等の意味のある文字列を失うことを優先して防止する。

文字数や英字比率による判定は主判定に用いない。短いタイトルや数字を含むタイトルが存在しうるためである。

### 8.4 除外ルール

除外ルールは設定ファイルから追加できるものとする。

新しい定型パターンが実ゲームで確認された場合、コード変更なしで追加できることを目標とする。

### 8.5 Filterの順序

Filterは以下の順序で適用する。

1. 空文字除外
2. confidence判定
3. 数値・単位等の定型パターン判定
4. 設定ファイル由来の追加ルール
5. 上記に該当しなければ翻訳候補として残す

## 9. 保護語（固有名詞の非翻訳）

### 9.1 対象

以下は原則として翻訳せず、原文のまま表示する。

- 星系名
- ステーション名 / 拠点名
- 船種名（Sidewinder、Anaconda、Type-9 Heavy等）
- 装備・モジュール名
- 武器名
- 派閥名 / 組織名
- 人名

コモディティ名（Gold、Basic Medicines等）は設定で切り替え可能とし、既定値は非翻訳とする。

### 9.2 方式

翻訳CLIへ送る前に保護語を機械的にマスクし、翻訳完了後に復元する。

プロンプト上の指示だけには依存しない。LLMが指示を無視して保護語を翻訳する可能性があるため、マスクを主方式とする。

マスクトークンは翻訳対象文字列中で自然発生しにくい形式とし、Line内で一意に識別できるものとする。

### 9.3 復元失敗

以下のいずれかに該当する場合、翻訳結果を破棄し、原文をそのまま表示する。

- マスクトークンが欠落している
- マスクトークンの個数が一致しない
- 未知のマスクトークンが追加されている
- 復元後の結果が検証条件を満たさない

破損した訳文をOverlayに表示しない。

### 9.4 辞書

既存の`dictionary/elite_terms.yaml`を利用する。

星系名は総数が膨大なため全件辞書化しない。将来、Journalから現在星系・目的地・ミッション関連の固有名詞を動的に収集し、一時的な保護語として登録する方式を検討する。

Journalの標準保存場所:

```text
%USERPROFILE%\Saved Games\Frontier Developments\Elite Dangerous\
```

## 10. 翻訳

### 10.1 エンジン

AI CLIを使用する。

`agy`または`claude`を設定で選択できるものとする。

### 10.2 Cache

翻訳結果はTranslation Cacheへ保存する。

同一原文が再出現した場合はCacheから即時取得する。

Cache HITのLineはMISSの翻訳完了を待たず、即座にOverlayへ反映する。

Cache MISSのLineはAI CLIによる翻訳完了後、追加でOverlayへ反映する。

### 10.3 並列処理

1回の監視フレームについて複数LineがMISSした場合、実装上可能な範囲で独立して処理できる構造とする。

ただしAI CLIの同時実行数は設定または実装上の上限を設け、無制限にプロセスを起動しない。

### 10.4 モデル指定

`config.yaml`の`translation.model`で指定する。

実在しないモデル名を指定した場合、翻訳は`success=False`として扱い、失敗したLineをOverlayへ表示しない。

起動時に翻訳単体の疎通確認を行い、失敗時は明示的にエラーを表示する。

## 11. 自己汚染の防止

### 11.1 問題

Overlayが元テキストの上に描画された状態で画面全体をキャプチャすると、次のOCRがOverlay自身を読み取る。

Linux版では、半透明Overlayが元の英語と重なり、英語断片と崩れた文字が混在した文字列を生成する問題が実測確認されている。

継続的にOCRを行う本仕様では、不透明Overlayでも自己汚染が発生する。不透明にすると元テキストが完全に隠れ、OCRが日本語訳を読み取るためである。

### 11.2 対策

EDウィンドウを対象としたウィンドウキャプチャを使用し、OverlayをEDとは別のトップレベルウィンドウとして実装する。

キャプチャ対象をEDウィンドウそのものに限定することで、別トップレベルウィンドウであるOverlayをキャプチャ入力へ含めない設計とする。

### 11.3 検証

受け入れ試験として以下を確認する。

1. Overlay表示中のキャプチャ画像を保存する。
2. 保存画像にOverlayが写り込んでいないことを確認する。
3. 同一テキストを長時間表示する。
4. OCR結果がOverlay表示の有無によって変質しないことを確認する。

## 12. Overlay

### 12.1 表示

翻訳候補として翻訳成功したLineのみを表示する。

Filterで除外されたLineは表示しない。

各Lineは、そのOCR結果のBBoxに対応する位置へ描画する。

座標変換は以下の順序とする。

```text
OCR bbox
  ↓
監視範囲相対座標
  ↓
EDクライアント座標
  ↓
スクリーン座標
  ↓
Windows Overlay
```

### 12.2 状態駆動

Overlayは「前回描画した内容を消す」方式を用いない。

毎回、現在の`OverlayState`全体を描画する。

```text
OverlayState = current translated lines

render(OverlayState)
```

`OverlayState`が空の場合は、Overlay描画領域を空にし、表示を非表示状態へ遷移させる。

差分更新や前回ピクセルの消去に依存しないことで、消去漏れを構造的に防止する。

### 12.3 追従

OCRは各フレームのBBoxを返すため、別途の文字位置追跡処理を必須としない。

その時点で得られたOCR結果のBBoxを使用することで、スクロール・画面移動に追従する。

### 12.4 遅延

OCR処理時間分、Overlayの位置と内容は実画面より遅れる。

スクロール中はOverlayが実際のテキスト位置からずれる可能性がある。

大きな画面変化を検出した場合はOverlayを一時的に非表示にし、画面が安定してから再表示する方式を実装可能とする。

この安定化機能は設定で無効化できるものとする。

### 12.5 消去

監視範囲内でテキストが検出されなくなった場合、該当Overlayを消去する。

ただしOCR結果0件を1回得ただけではOverlayを消去しない。OCR取りこぼしと真の空状態を区別できないためである。

既定では連続3回、対象Lineが検出されない場合に消去する。

### 12.6 OCR失敗時

OCR処理そのものが例外・タイムアウト等で失敗した場合、空結果として扱って即時消去してはならない。

最後に正常取得した`OverlayState`を維持し、連続失敗回数を記録する。一定回数を超えた場合の扱いは実装時に定義する。

## 13. 原文Window

### 13.1 目的

OCRした原文をそのまま一覧表示する。

星系名・ステーション名等をコピーする用途を想定する。

### 13.2 表示内容

原文のみを表示する。翻訳は表示しない。

Filterで除外されたLineも含め、監視範囲から取得した全Lineを表示する。

これにより、除外ルールが正しく機能しているかを確認できる。

各Lineは原則としてOCR結果順に表示する。

### 13.3 表示制御

ショートカットキーで表示／非表示を切り替える。

常時表示しない。

原文Windowを閉じても監視・翻訳・Overlayは停止しない。

### 13.4 操作

- 行を選択してコピーできる
- 全文をコピーできる

### 13.5 OCR共有

原文Windowは独自のOCRを実行しない。

監視ループが生成した同一OCR結果を共有する。

原文Windowの表示・非表示によってOCR負荷が増加してはならない。

## 14. 設定

設定はYAML形式とする。

最小構成例:

```yaml
ocr:
  region:
    x: 360
    y: 850
    width: 1200
    height: 150
  interval_ms: 500
  confidence_threshold: 0.50
  clear_after_missing_frames: 3
  stable_hide_on_large_change: true

filter:
  rules: []

translation:
  engine: agy
  model: ""
  cache: true
  max_concurrency: 1

protected_terms:
  commodities: false
```

数値・閾値は初期値であり、実測結果に応じて変更可能とする。

設定ファイルの実際のスキーマは実装時に確定する。

## 15. 既知の制約

| 制約 | 内容 |
|---|---|
| 排他的フルスクリーン非対応 | ボーダーレス／ウィンドウモードが必須 |
| スクロール中のずれ | OCR遅延分、Overlay位置が遅れる |
| 解像度・ウィンドウサイズ変更 | 監視範囲の自動補正を行わず、必要に応じて再指定する |
| 星系名の網羅 | 全星系の完全辞書化は行わないため、保護漏れが発生しうる |
| 範囲指定中の入力 | EDの通常操作を受け付けない。ゲーム内時間は進行する |
| OCR処理時間 | 500msを超える場合、実効OCR頻度は2fps未満になる |
| OCR誤認識 | OCR結果自体の誤認識は本仕様では完全には排除しない |

---

## 16. 本仕様に含まれないもの

- 全画面の自動テキスト領域検出
- 監視範囲の自動決定
- 画面種別の自動判定
- 監視範囲の自動位置補正
- Linux版との共通化・移植
- OCRエンジンの変更
- Mission Board専用の表形式ウィンドウ
- ゲーム内入力の自動化

## 17. 将来拡張

### 17.1 自動OCR

RapidOCRはDetectionとRecognitionを内蔵しており、全画面入力に対して文字領域を自動検出する構成が可能である。現在のRapidOCR出力には各テキスト行のBBoxが含まれるため、別途`TextRegionDetector`を新設する必要がない可能性がある。citeturn0search0turn0search2

ただし、全画面DetectionのWindows環境での負荷・精度は未測定であるため、本仕様の実装範囲には含めない。

将来の実装では、まず全画面Detectionのみをベンチマークし、現在の手動監視範囲方式とのCPU時間・OCR時間・誤検出率を比較して採否を決定する。

### 17.2 選択範囲コピーからのWindow起動

選択範囲をOCRした際に、原文Windowを自動で開く動作を追加する。

### 17.3 Journal連携

Journalログから固有名詞を動的に収集し、保護語辞書を補完する。

## 18. 実装フェーズ

### Phase 0: Windows環境確認

- ED対象ウィンドウ取得
- クライアント領域サイズ取得
- ウィンドウキャプチャ単体確認
- キャプチャ画像保存確認
- ED移動時の追従確認

**合格条件:** EDウィンドウのみを安定して取得できる。

### Phase 1: 監視範囲

- 範囲指定UI
- 設定保存・復元
- 座標検証
- ウィンドウサイズ変更検出

**合格条件:** 指定した範囲がEDクライアント座標として正しく再現される。

### Phase 2: RapidOCR単体

- RapidOCR接続
- `text / bbox / confidence`取得
- Detection / Classification / Recognition時間計測
- OCR結果可視化

**合格条件:** 実ゲーム画像からLineとBBoxを安定取得できる。

### Phase 3: 監視ループ

- 500ms周期
- single-flight
- 差分Gate
- OCR結果共有

**合格条件:** 静止画面で不要なOCRが連続実行されず、画面変化時にOCRが実行される。

### Phase 4: Filter / 保護語

- Filter
- 設定ファイルルール
- 保護語Mask / 復元
- 復元失敗時の原文フォールバック

**合格条件:** 除外対象が翻訳されず、保護語が翻訳されない。

### Phase 5: Translation / Cache

- AI CLI接続
- Cache HIT / MISS
- 非同期反映
- モデル疎通確認

**合格条件:** Cache HITがMISSの完了を待たず表示され、MISSも翻訳完了後に表示される。

### Phase 6: Windows Overlay

- 別トップレベルウィンドウ
- BBoxからスクリーン座標への変換
- 状態駆動描画
- 空状態のclear/hide
- 自己汚染検証

**合格条件:** OverlayがEDキャプチャへ混入せず、Lineの出現・移動・消失に追従する。

### Phase 7: 原文Window

- OCR結果共有
- 行選択コピー
- 全文コピー
- 独立した表示制御

**合格条件:** 原文Windowを表示してもOCR負荷・翻訳処理が増えない。

### Phase 8: 実ゲーム総合試験

- Mission Board
- ステーション画面
- 星系名・ステーション名
- スクロール
- 画面遷移
- 長時間連続実行
- Overlay自己汚染
- OCR取りこぼし時の消去動作

**合格条件:** 既知の制約を除き、継続OCR・翻訳・Overlay・原文コピーが安定動作する。

## 19. 受け入れ条件

以下をすべて満たした時点でWindows版手動OCRを実装完了とする。

1. EDの対象ウィンドウだけをキャプチャできる。
2. Overlayがキャプチャ画像へ混入しない。
3. ユーザー指定の監視範囲を再起動後も復元できる。
4. 監視範囲の変化を検出してOCRを実行できる。
5. OCR結果として`text / bbox / confidence`を取得できる。
6. BBoxを使用して翻訳を元テキスト位置へ表示できる。
7. Filterにより不要な定型文字列を翻訳対象から除外できる。
8. 未知パターンを原則として翻訳対象に残せる。
9. 保護語を機械的に保護できる。
10. 保護語復元に失敗した訳文を表示しない。
11. Cache HITを即時表示できる。
12. Cache MISSを翻訳完了後に追加表示できる。
13. OverlayStateを状態駆動で描画し、消去漏れを防止できる。
14. OCR取りこぼし1回でOverlayが消えない。
15. 原文WindowでOCR結果をコピーできる。
16. 原文Window表示によってOCR処理が二重化しない。
17. Windows環境でOCR性能を実測し、結果を記録できる。
18. 長時間連続実行でOverlay自己汚染によるOCR結果の変質が発生しない。
