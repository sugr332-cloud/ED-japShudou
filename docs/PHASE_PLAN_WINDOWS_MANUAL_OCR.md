# ED_Japanese Windows版 手動OCR フェーズ計画

**対象仕様:** `docs/SPECIFICATION_WINDOWS_MANUAL_OCR.md`

## 進め方の原則

1. 1フェーズごとに動作確認してから次に進む。複数フェーズをまとめて実装しない。
2. 各フェーズは単体で合否を判定できること。判定手段がないフェーズを作らない。
3. 実測していない値を仕様・報告に断定形で書かない。推測値は「未測定」と明記する。
4. 前フェーズで確認できていないことを前提にしない。

## W0 — 現状把握

### 目的
既存リポジトリに何が実装済みかを確定させる。推測で設計を進めないため。

### 作業
- `app/` 配下のOCR関連ファイルを全て列挙する。
- 各ファイルの役割を実際のコードから確認する。
- RapidOCR呼び出し箇所がbboxを保持しているか、破棄しているかを確認する。
- Normalizer / Stabilizer / DocumentTrackerの入出力を確認する。
- Translation Cacheのスキーマと保存内容を確認する。
- `dictionary/elite_terms.yaml` の現在の内容と規模を確認する。
- 既存の`manual_ocr.py`が実際に何をしているか確認する。

### 合格条件
- Windows版で再利用できるモジュールと、新規実装が必要なモジュールが一覧で示されている。
- bboxが利用可能かどうかが、コードの実物に基づいて確定している。

### やらないこと
- コードの変更。
- 設計の提案。

## W1 — Windowキャプチャ

### 目的
EDウィンドウを対象としたキャプチャを成立させる。

### 作業
- EDのウィンドウハンドルを取得する。
- ウィンドウ内容をキャプチャし、画像として保存する。
- ウィンドウ相対座標を扱えるようにする。

### 合格条件
- EDの画面が画像として取得できる。
- 10分間の連続取得で落ちない。
- Alt+Tabでフォーカスを外しても取得が継続する。
- EDウィンドウを移動しても取得が継続する。
- デスクトップ上の他のウィンドウが写り込まない。

### 測定
- 1回あたりのキャプチャ所要時間。
- 連続取得時のCPU使用率。

### やらないこと
- OCR接続。
- 範囲選択。

### 注意
排他的フルスクリーンでキャプチャできない場合、その事実を記録する。ボーダーレス必須という制約が確定する。

## W2 — 監視範囲の指定と保存

### 目的
ユーザーが矩形を指定し、保存・復元できるようにする。

### 作業
- ショートカットで範囲指定モードに入る。
- 矩形の位置とサイズを調整する。
- 確定して保存する。
- 起動時に復元する。

### 合格条件
- 指定した矩形が設定ファイルに保存される。
- アプリを再起動すると同じ矩形が復元される。
- 保存された値が実際の指定位置と一致している。クロップ画像を保存して目視確認する。
- 範囲指定モードから抜けるとEDに入力が戻る。

### やらないこと
- OCR接続。
- 翻訳。
- Overlay。

### 注意
W2はOCRに接続しないため、合否確認はクロップ画像の保存で行う。指定範囲を切り出して保存し、意図した領域が写っているかを目視で確認する。

## W3 — OCR接続とベースライン測定

### 目的
監視範囲のOCRを成立させ、性能の基準値を得る。

### 作業
- 監視範囲をRapidOCRに渡す。
- text / bbox / confidenceをコンソールに出力する。
- Detection / Classification / Recognitionの内訳時間を記録する。

### 合格条件
- 監視範囲内の文字が読み取れる。
- bboxが取得でき、監視範囲内の相対座標として正しい。
- 内訳時間が記録されている。

### 測定
| 項目 | 測定内容 |
|---|---|
| 総時間 | 1回のOCR所要時間 |
| Detection | 検出段の時間 |
| Classification | 角度分類の時間 |
| Recognition | 認識段の時間 |
| 範囲サイズ依存 | 監視範囲を変えたときの変化 |

### 判断
内訳の結果により、以降の高速化方針を決める。
- Recognitionが支配的 → 行単位の処理削減が有効。
- Detectionが支配的 → 入力サイズ削減が有効。
- Classificationが無視できない → 無効化を検討する。ただしEDのUIテキストが常に水平であることを実測・仕様確認してから判断する。

### やらないこと
- 高速化の実装。測定のみ。
- 翻訳。
- Overlay。

## W4 — 差分ゲートと監視ループ

### 目的
2fpsの継続監視を成立させる。

### 作業
- 500ms間隔のキャプチャループ。
- 前フレームとの差分判定。
- 変化がない場合はOCRをスキップする。
- OCR実行中は次のOCRを重複実行しない。

### 合格条件
- 静止画面でOCRが実行されない。
- 画面が変化したときにOCRが実行される。
- OCRが500msを超えてもループが破綻しない。
- 10分間の連続動作で落ちない。

### 測定
- 静止時のCPU使用率。
- 動作時の実効フレームレート。
- 差分判定の所要時間。

### 注意
背景が動いている状態（星や船が見える画面）では差分が常に発生する可能性がある。この場合の挙動を実測し、不感帯が必要かを判断する。

## W5 — Filterと保護語

### 目的
翻訳すべきものだけを選別する。

### 作業
- 除外ルール（金額・距離・記号・数値等）の実装。
- 未知パターンは翻訳対象として残す。
- 保護語のマスク／アンマスクを実装する。
- マスク復元失敗時のフォールバックを実装する。

### 合格条件
- `348,097 CR`、`7.54 LY`、`REP ++`が除外される。
- ミッションタイトルが除外されない。
- 保護語がマスクされ、正しく復元される。
- マスクトークンが欠落した場合、原文が表示される。破損した訳文を出さない。

### テスト
実際のOCR結果をサンプルとして、Filterの入出力を単体テストする。実ゲームを起動せずに検証できるようにする。

### やらないこと
- 翻訳CLIへの接続。
- Overlay。

### 並行実施について
W5はW3で取得した実OCRサンプルが存在し、W3の合格条件を満たした後であれば、W4と並行して実装・単体テストしてよい。

ただし、W4の合格をW5の合格条件として省略することはしない。W6以降へ進む際は、W4とW5の双方が合格していることを確認する。

## W6 — 翻訳接続

### 目的
Filterを通過したテキストを翻訳する。

### 作業
- AI CLI（agy / claude）への接続。
- Translation Cacheの利用。
- Cache HITの即時反映。
- Cache MISSがHITの表示をブロックしない構造。

### 合格条件
- 起動時に翻訳の単体疎通が確認され、失敗時に明示的なエラーが出る。
- 翻訳が`success=True`を返す。
- 同一テキストの再出現でCache HITになり、再翻訳されない。
- 保護語が原文のまま維持されている。
- 遅い翻訳が、既に翻訳済みのテキストの表示を待たせない。

### 注意
存在しないモデル名を指定すると全体が沈黙することを防ぐため、設定されたモデルが実在することを一覧等で確認してから使用する。

### やらないこと
- Overlay。

## W7 — Overlay

### 目的
翻訳結果を元テキストの位置に表示する。

### 作業
- 別ウィンドウとしてOverlayを実装する。
- OverlayStateによる状態駆動の描画。
- bboxからスクリーン座標への変換。
- 変化検出中の一時非表示。
- 連続N回未検出での消去。

### 合格条件
| # | 確認内容 |
|---|---|
| 1 | 翻訳がテキストの位置に表示される |
| 2 | テキストが消えるとOverlayも消える |
| 3 | スクロールすると、静止後に正しい位置へ追従する |
| 4 | 表示が続いている間、消えるべきでないときに消えない。数分間の連続表示で誤消去が発生しない |
| 5 | 除外されたテキスト（金額・距離・記号）がOverlayに出ない |
| 6 | Overlay表示中のキャプチャ画像にOverlayが写り込まない |
| 7 | Overlayを長時間表示してもOCR結果が変質しない。自己汚染なし |

### 特に重要
条件6と7は自己汚染の検証である。ここが成立しないと、継続OCRと重ね表示は両立しない。キャプチャ画像を保存して実際に目視確認する。

条件4は誤消去の検証である。誤って残るより、誤って消える方が体験を壊す。

### 測定
- 画面変化からOverlay更新までの実測遅延。

## W8 — 原文Window

### 目的
OCR原文の一覧表示とコピーを可能にする。

### 作業
- ショートカットでの表示／非表示。
- 原文のみの一覧表示。Filterで除外されたものも含める。
- 行選択コピー／全文コピー。
- 監視ループとOCR結果を共有する。

### 合格条件
- ショートカットで開閉できる。
- 原文が表示される。翻訳は表示されない。
- 星系名・ステーション名をコピーできる。
- Windowを閉じても監視・翻訳・Overlayが停止しない。
- Windowを開いてもOCR実行回数が増えない。

## W9 — 実ゲーム総合Gate

### 目的
一連の動作を実ゲームで確認する。

### シナリオ
| # | 確認内容 |
|---|---|
| 1 | 範囲を指定して監視を開始できる |
| 2 | Mission Boardのタイトルが翻訳表示される |
| 3 | 金額・距離・記号が翻訳されない |
| 4 | 星系名・ステーション名・船名が原文のまま表示される |
| 5 | スクロール後、静止したら正しい位置に追従する |
| 6 | 画面を閉じるとOverlayが消える |
| 7 | 再度同じテキストが出たときCache HITで即座に表示される |
| 8 | 原文Windowで星系名をコピーできる |
| 9 | 30分の連続使用で落ちない |
| 10 | 自己汚染が発生しない |

### 記録
- 各シナリオの成否。
- スクリーンショット。
- OCR所要時間の実測。
- 発生した問題と切り分け結果。

## 実装順序まとめ

```text
W0  現状把握
     ↓
W1  Windowキャプチャ
     ↓
W2  監視範囲の指定と保存
     ↓
W3  OCR接続とベースライン測定
     ↓
W4  差分ゲートと監視ループ
     ↓
W5  Filterと保護語
     ↓
W6  翻訳接続
     ↓
W7  Overlay
     ↓
W8  原文Window
     ↓
W9  実ゲーム総合Gate
     ↓
[将来] 自動OCR / Journal連携
```

W5はW3の出力サンプルがあれば、W4と並行して実装・単体テストできる。それ以外は原則として順に進める。

## 各フェーズ共通の禁止事項

- 前フェーズの合格条件を満たさないまま次へ進まない。
- 実測していない数値を報告に断定形で書かない。未測定は「未測定」と書く。
- 今回のフェーズで指示されていないファイルを変更しない。
- 報告には今回実際に実行・測定したものだけを書く。過去の結果を混ぜない。
